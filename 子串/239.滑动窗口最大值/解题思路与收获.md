# 239. 滑动窗口最大值 · 解题思路与收获

## 思路（单调队列）

- 双端队列存**下标**；不变式：队列内下标递增、对应值**递减** → **队头永远是当前窗口最大值**
- 每轮三步：① 队尾清场（弹出所有比新元素小的）② 新下标入队 ③ 队头过期弹出（`q[0] <= i-k`）
- `i >= k-1` 窗口铺满后开始收答案 `nums[q[0]]`
- 时间 O(n)（每个下标至多进队一次、出队一次——均摊老朋友），空间 O(k)

## ⭐ 收获一：双端队列 deque 语法

| 操作 | 右端（队尾）| 左端（队头）|
|------|-----------|-----------|
| 进 | `d.append(x)` | `d.appendleft(x)` |
| 出 | `d.pop()` | `d.popleft()` |
| 看 | `d[-1]` | `d[0]` |

- 记忆法：**右端是默认方向**（`append`/`pop` 与 list 相同），加 `left` 后缀即左端
- 它和 list 的本质区别：**两头进出都是 O(1)**（list 头部操作要 O(n) 搬家）
- 选用信号：需要在**头部**高效进出时（队列、BFS、单调队列、滑动窗口最值）

## ⭐ 收获二：为什么存下标而不是值

- **值不会过期，位置会**——只存值就无法判断"队头的最大值是否已滑出窗口"
- 存下标 → 与窗口边界 `i-k` 一眼可比
- **连带义务**：收答案时要翻译回值 `nums[q[0]]`——我漏了这步，输出了一串下标

## ⭐ 收获三：单调性的思想（新武器，将来复用）

- **"又老又小"死刑论**：新元素比队尾更大且更年轻，队尾比它小的那些永远当不了最大值，弹掉零风险
- 单调队列 = 维护"还有希望成为答案的候选名单"；兄弟武器是**单调栈**（84. 柱状图最大矩形、739. 每日温度在后面等着）
- 每个元素至多进出一次 → O(n)，这就是"每次重扫求 max"（O(nk)）做不到的事

## 教训

1. **窗口边界要画格子数**：窗口 = `[i-k+1, i]`，过期 ⇔ `q[0] <= i-k`。我写 `< i-k` 恰好漏掉一格——照妖镜用例 `[5,1,1,1], k=3 → [5,1]`（过期的大值赖在队头多当一任）
2. `from collections import deque` 不能省：LeetCode 不自动导入，本地也 NameError
3. `if` vs `while` 判过期：窗口每轮只滑一格，一次最多过期一个下标 → `if` 足够；`while` 是防御性等价写法（面试能讲出这句是加分）
