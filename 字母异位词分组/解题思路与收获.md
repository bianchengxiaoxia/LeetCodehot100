# 49. 字母异位词分组 · 解题思路与收获

## 思路

- 分组问题 → 想到哈希表（字典 = 档案柜，一柜一组）
- **难点在键的选择**：键 = 组的"指纹"，指纹相同 ⇔ 同组
  - 写法一（排序）：`key = ''.join(sorted(word))`，eat/tea/ate → "aet"
  - 写法二（计数）：`key = tuple(cnt)`，数 26 个字母各出现几次
- 一次遍历，逐词归柜，最后 `list(groups.values())` 即答案

## 收获

1. **哈希题的核心是设计键**。键选得好，复杂度直接降档：本题从两两比较的 O(n²k) 降到 O(n·k)。套路：找"什么变换能抹掉无关差异"（排序抹掉顺序，计数抹掉顺序）
2. **复杂度低 ≠ 跑得快**。真实耗时 = 每词固定开销 + 每字符成本 × 词长 k：
   - 词很短时，计数法的建表/转 tuple 起步价还没摊薄，sorted（C 层）反而更快
   - 词长 k 大了，O(k) 对 O(k log k) 的优势才兑现
   - 词数 n 只等比放大双方耗时，不改变胜负
3. **新学的语法**：
   - `''.join(sorted(word))`：sorted 返回字符列表 `['a','e','t']`，join 用空串粘回 `"aet"`
   - `d.setdefault(key, []).append(x)` ≡ `if key not in d: d[key] = []` 再 `append`
   - `ord(ch) - ord('a')`：字母 → 0~25 下标（`chr` 是反方向）；`ord('a')` = 97
   - **字典的 key 必须可哈希**：list 不可哈希不能当 key，转成 tuple 才行

## 关联

- 和两数之和对比：同为"遍历 + 查档案柜"，那题 key 是数值、value 是下标；本题 key 是指纹、value 是词列表
