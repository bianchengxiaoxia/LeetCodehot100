# 15. 三数之和 · 解题思路与收获

## 思路（标准解法）

- **排序**（一石三鸟：对撞的前提、去重的前提、本题返回值不返回下标所以安全）
- **for 固定第一个数 i**，内层 left/right **对撞**找两数之和 = `-nums[i]`
- **三处跳重**：i 层 `nums[i] == nums[i-1]` 跳过；找到解后 left、right 各自跳过相邻相等
- 剪枝：`nums[i] > 0` 直接 break
- 时间 O(n²)，空间 O(1)

## 降维打击：从两数到 k 数

| 规模 | 做法 | 复杂度 |
|------|------|--------|
| 两数之和 | 哈希一遍扫 或（有序时）对撞 | O(n) |
| 三数之和 | 固定 1 个 + 对撞 | O(n²) |
| 四数之和 | 固定 2 个 + 对撞 | O(n³) |
| k 数之和 | 固定 k−2 个 + 对撞 | O(n^(k−1)) |

**通用框架（递归降维）**：k > 2 时固定一个数、递归做 (k−1) 数之和；降到 k == 2 时对撞收尾。写成通用的 `kSum` 函数，三数/四数只是参数不同。每一层固定都可以复制"跳相邻相等"去重 + 剪枝。

注意：这条路线适用于"枚举所有解"。若题目只问"**是否存在**"或"**计数**"，哈希/前缀和/动规往往更优——先看题目要什么再选武器。

## 我的进化史（本题最大财富）

1. **哈希版**（固定两个数 + set 查第三个）：四个 bug 逐个磨掉——
   - `result.add([...])` 列表进集合 → TypeError（元素必须可哈希，转 tuple）
   - `middle` 不复位 → 外层第二轮起空转（内层起点要放外层循环开头）
   - 去重没规范化 → `(-1,0,1)` 和 `(-1,1,0)` 是集合里两个不同元素（入集合前 `tuple(sorted(...))`）
   - 返回元组的列表 → 判题要 `List[List[int]]`（最后 `[list(t) for t in result]`）
   修完后 200 组对拍全绿——但 **O(n³) 必超时**，这条路走到头了
2. **O(n³) 的分析**：嵌套循环只对一半，**循环体不是免费的**——`set(nums[middle+1:])` 切片+建表 O(n)，嵌在 O(n²) 里；插入总次数 = C(n,3)，第三层枚举藏在 set() 的 C 实现里
3. **标准版手敲四错**：`else if`→`elif`（Python 没有 else if）、`n` 未定义（定义的是 length）、孤立的 `v`、`return` 缩进在 for 里（第一轮就提前返回）——语法错误一次只报一个，修一个蹦一个

## 收获清单

1. **降维思想**：三数 = 固定一个 + 两数问题；k 数 = 固定一个 + (k−1) 数问题。"固定一个、子问题降一维"是超越双指针的通用套路
2. **去重的本质**：答案只认值不认下标 → 同值只需第一次出现当锚点（窗口最大）。口诀：**跳"办过事"的，留"当原料"的**
3. **跳重一和前一个比**（`nums[i]==nums[i-1]`）：跳的是"坐过第一数位置的"；和后一个比会把原料也赶出窗口
4. **凡见 `nums[i-1]` 必有 `i > 0`**：Python 负下标静默绕到数组尾部，不崩的 bug 更危险（`[0,0,0]` 实测丢解）
5. **循环体里藏着 O(n)**：`set(切片)`、`sorted()`、列表拼接——数复杂度要连循环体一起算
6. **`sorted(x, y, z)` ≠ `sorted((x, y, z))`**：三个参数 vs 一个元组（同类：`extend(i,j)` vs `extend([i,j])`）
7. **工程习惯**：在本地 VS Code 写（红波浪线当场抓语法错），别在 LeetCode 编辑器盲敲；AC 后记得同步回本地文件
8. 注释要写"为什么"而不是"是什么"——给一周后二刷的自己看
