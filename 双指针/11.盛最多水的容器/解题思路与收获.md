# 11. 盛最多水的容器 · 解题思路与收获

## 思路

- 对撞指针：`left/right` 从数组两端向中间夹逼
- 每轮三步：**① 记录当前对面积**（宽度 × `min(两边)`）→ **② 扔短板一侧** → **③ 移动该指针**
- 时间 O(n)，空间 O(1)

## 收获

### 1. 对撞指针 vs 快慢指针——双指针的两种范式

| | 对撞指针 | 快慢指针 |
|---|---------|---------|
| 变量名 | left / right | slow / fast |
| 移动方向 | 两端 → 中间，相向而行 | 同向，一前一中 |
| 适用场景 | 区间、容器、对称结构（本题、42.接雨水、15.三数之和） | 原地整理、划界扫描（283.移动零、27.移除元素） |

同一个"双指针"专题，两副面孔，命名分开记，口述思路不乱。

### 2. 木桶效应

容器容量 = 宽度 × `min(height[left], height[right])`——**水面高度由短板决定**。忘了 min 会高估出"不存在的容器"。

### 3. 扔短板为什么不丢最优解（本题灵魂）

- 宽度每移动一次必然变小，想翻盘只能指望高度
- **移动长板**：`min` 不变或更小，宽度还缩了 → 不可能更优，白扔
- **移动短板**：这块短板配的是它一生中最宽的对子，已是天花板 → 弃之不亏
- 所以每一步淘汰的都是"不可能藏着最优解"的候选，循环结束 `best` 必然包含全局最优

### 4. 双指针循环三步曲（顺序不能乱）

```
① 记录当前状态（算面积/长度/结果）
② 决策（本轮淘汰谁）
③ 移动指针
```

先移动再计算，"当前对"就变成"上一对"，所有索引运算都要倒放解码，错误率暴涨。

### 5. 我发现的"回头补算"变体（等价但难读）

移动之后用 `(fast-slow+1) × height[slow-1]` 回头重构刚被淘汰那对的面积——数学上**完全等价**（分支条件保证了 `height[slow-1]` 恰是那一对的短板，连 min 都省了），对拍 2000 组全对。但每处索引都要读者倒放一步才能懂，**能对 ≠ 好读**：面试里索引花活越多，被追问时翻车面越大。最终改写成直叙版。

### 本题四版进化史（自己的debug记录）

崩溃版（右指针起点越界 `len` 应为 `len-1`）→ 错位版（先移动后计算 + 缺 min）→ 回头补算版（独立做对，但绕）→ 直叙版（脱稿复写）。教训：**右指针从 `len-1` 出发**、**面积先记录后移动**、**别在公式上打补丁，改结构**。

## 语法

- 两点之间宽度 = 下标差（柱子的**间距**，不是柱子根数，别 +1）
- `left, right = 0, len(height) - 1`：多变量同时赋值
